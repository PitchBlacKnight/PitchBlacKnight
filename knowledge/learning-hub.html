Pillar · The design-to-code bridge01

Figma MCP — the file becomes queryable

The Model Context Protocol is a wire protocol: a standard way for a program that holds context (Figma) to expose it to a program that reasons (Claude, Cursor). It turns your design file from something an agent looks at and guesses into something it asks and gets an answer. This is your resume's Dev Mode / Code Connect claim, upgraded.

New · Write to Canvas Remote server · all plans Local desktop server Code Connect

Where it stands

  • Two servers. A remote one Figma hosts at mcp.figma.com/mcp — works on every plan including free Starter, needs only an account and a personal-access token with file:read. And a local desktop server at 127.0.0.1:3845/mcp that runs beside the Figma desktop app.
  • What it exposes. get_design_context (structured design → code), get_variable_defs (your tokens/variables), get_code_connect_map, get_metadata, get_screenshot. The remote server also creates files, uploads assets, searches your design system, and turns live web UI into editable Figma layers.
  • Write to Canvas (the new frontier). Agents now build and update frames, components, variables and auto-layout in your file — using your design system as the source of truth. Free during beta, for Full and Dev seats on paid plans. This is the moment MCP stopped being read-only.
  • Code Connect is the piece that matters most for you: it makes generated code use your actual components, imports and prop interfaces — not an invented <Btn> when your repo has <Button intent>.

Learn it by doing this week

  1. Point Claude Code at one real Figma file (a Verizon frame). Run get_metadata, then get_design_context. Save both to notes/ — read what the agent actually receives.
  2. Run get_variable_defs on a properly tokened file. Diff what comes back against what you thought was in there. The gaps are the lesson.
  3. Wire one component end-to-end with Code Connect. Any component. The first mapping is the whole concept.
  4. Try Write to Canvas: prompt an agent to build a small frame constrained to your variables. Note what it got right and where it drifted.

Say it in an interview

"Why does MCP matter for design systems?"

"For twenty years the design-to-dev handoff was lossy by design — someone re-typed decisions between two systems with no shared vocabulary. MCP closes it by making the file queryable instead of viewable. It's the token argument — decisions live in one place and get consumed, never re-typed — extended past the boundary of the design tool."

Pillar · Prompt-to-app02

Figma Make — assessed, not hyped

Make generates working screens and apps from a prompt. It's now generally available — which means the interview question is no longer "have you seen it?" but "what's your position on it?" Have a real one, not a shrug. That's the entire differentiator here.

Generally available Publishing · still beta Credit-metered

Where it stands

  • Out of beta. Make — along with Edit Image and Boost Resolution — moved to general availability. Publishing Make files is still beta, unlocked for Full seats.
  • The credit model is the real constraint. Starter plan: 500 credits/month, capped at 150/day — enough to poke, not to iterate on real work. Professional Full seat (~$16/mo annual) gives ~3,000 credits/month, which covers most single-user prototype work. Shipping Make output into a codebase is free during beta; standard credit usage applies once the agent goes GA.
  • The honest limit. Expect roughly a 70–80% structural match — great for validating a concept, expensive and imperfect for production component work. Iteration burns credits fast.

Learn it by doing this week

  1. Generate one screen from a prompt. Time it. Note the first thing you'd have to fix.
  2. Regenerate the same screen constrained to your tokens. Where does it drift off-system? That drift is your governance story.
  3. Push output toward a real codebase and measure the last mile — the gap between "looks right" and "is right" is exactly what you get paid to close.

Say it in an interview

"What's your take on Figma Make?"

"I reach for it to validate a concept or throw a prototype in front of stakeholders in an afternoon — where the ~80% match is a feature, not a flaw. I refuse it for production component work, because the last 20% is the part a design system exists to guarantee. It compresses the front of the process; it doesn't replace the governance at the back."

Pillar · Directing the machine03

AI vibe coding — the orchestrator's craft

The mechanical skill of typing code is being commoditized. The intellectual skill — system design, orchestration, critical review — is where the value moved. For a designer who can direct an agent and judge what it produces, this is the single biggest differentiator you can hold in 2026.

Claude Code Cursor Codex Blended workflows are the norm

Where it stands

  • The tool landscape. Cursor — AI-native IDE, deep repo awareness, multi-file refactors, inline diffs. Claude Code — terminal-native agent, best for repo-wide refactors and architecture, handles 50k+ LOC codebases reliably. Codex — reached for where raw model depth matters. The practitioner consensus is a blended workflow, not loyalty to one.
  • The workflow underneath. Clear intent → small changes → honest review → knowing how to catch the AI when it drifts. That loop is the skill, independent of tool.
  • What's actually valued now. System design, AI orchestration, security judgment, domain knowledge. Whoever can direct agents and critically review generated code is in higher demand than whoever types fastest.

Learn it by doing ongoing

  • Build one small thing end-to-end in an agent — you are doing it right now. This field guide was generated in Claude Code. That's the artifact and the proof.
  • Practice the loop deliberately: plan → one small diff → review → correct. Resist the big-bang generate.
  • Keep a running "where the AI drifted" log. Each entry is an interview story about judgment — the thing they're actually screening for.

Say it in an interview

"How do you work with AI coding tools?"

"As the orchestrator, not the typist. I give clear intent, keep changes small, and review honestly — I've learned where these agents drift, so I catch it. As a designer that's my edge: I can wire the design system into the agent through MCP and Code Connect, then judge whether what comes out is actually on-system. The typing is commoditized; the judgment isn't."

Pillar · The ground you already own04

Design systems in 2026 — now consumed by agents

Everything you already know here still holds — but the consumer changed. Your system is no longer read only by humans; it's queried by agents. Naming, machine-readability, and drift are the new governance frontier, and they map directly onto your tokens and governance claims.

DTCG token standard MCP as machine-readable docs Autonomous drift agents A11y baked into tokens

Where it stands

  • Proprietary naming is out. Teams are standardizing on the Design Tokens Community Group (DTCG) JSON format for tool interoperability. Tokens are now the JSON an agent references every time it generates something.
  • Docs became a machine-readable intelligence hub. Via MCP, agents "understand" your system and generate code, tickets and docs that are 100% on-system in real time. Documentation that a machine can't parse is now a liability.
  • Autonomous drift detection. The leading edge is agents that watch the system across Figma, Jira and GitHub — spotting design drift before it reaches production, and correcting it without a prompt.
  • Accessibility is foundational, not a review step. With the European Accessibility Act in force (June 2025), a11y constraints are being built into the tokens themselves.

Learn it by doing this week

  1. Take one token set and restructure it into clean DTCG JSON — primitive → semantic → component. Notice what your old naming can't express.
  2. Bake one accessibility constraint (a contrast floor) into a semantic token so it can't be violated downstream.
  3. Write down, in a paragraph, how an agent would detect drift in a system you've built. That paragraph is a senior-level interview answer.

Say it in an interview

"What's changed about design systems?"

"The consumer. A system used to be read by designers and engineers; now it's queried by agents. That makes machine-readability a first-class governance concern — DTCG naming, tokens as JSON, docs exposed over MCP. My governance instincts didn't change; the interface for them did. Detach rate is still my health signal — now drift detection can be automated against it."

Pillar · Putting it together05

The Figma loop — streamlining the real work

The four pillars above aren't separate skills — they're one loop. Design → code → design, with the design system wired in as the source of truth at every step. Being able to describe and run this loop end-to-end is what "AI-augmented contribution" actually means on your resume.

The loop, concretely

  • Design → code. Agent pulls a frame over MCP (get_design_context + get_variable_defs), Code Connect ensures it emits your real components. You review the drift.
  • Code → design. Write to Canvas pushes structure back into Figma, or turns live web UI into editable layers. You check what survived the round-trip.
  • System watches both. Drift-detection agents span Figma / Jira / GitHub and flag when either side wanders off-system before it ships.

Learn it by doing real reps

  1. Run the full loop once on a real frame. Log the three failure modes you actually hit — those are your best interview stories, because they're specific and they're yours.
  2. Write your "AI-augmented contribution pattern" as a concrete procedure, not a buzzword: who reviews agent-authored components, what gate they pass, how a token change propagates.

Say it in an interview

"How would you wire a design system to an AI coding agent?"

"Three moves. Expose the system over MCP so the agent queries tokens and context instead of guessing from a screenshot. Wire Code Connect so generated code uses our real components and prop interfaces. Then treat agent-authored contributions like any other PR — same review gate, same versioning — with drift detection watching the seam between design and code. The agent speeds the work; the governance is unchanged."

The terminal, demystified

You're already using Claude Code — the terminal is just the same tool with a plainer face. 95% of the time you type normal sentences, like you do in the app. The rest is a handful of shortcuts. Here's all of it on one screen. Launch it with cd into your project, then claude.

The seven you'll actually use type / to see the menu

/helpLists everything. Your safety net — start here anytime.
/clearWipes the conversation for a fresh start. Use it when you switch tasks so old context doesn't bleed in.

/initScans the project and writes a CLAUDE.md so every future session starts smarter. Run once per project.
/resumeReopen a past conversation instead of starting over.
/costShows how much you've used this session.
/exitLeaves Claude Code. Or press Ctrl + C twice.
