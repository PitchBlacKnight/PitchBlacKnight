Now, the idea.

The Model Context Protocol is not an AI feature. It's a wire protocol — a standard way for a program that holds context (Figma, a database, your filesystem) to expose that context to a program that reasons (Claude, Cursor, whatever comes next). That's the whole thing.

Why it matters to you specifically: for twenty years the design-to-dev handoff has been lossy by design. You export a spec, someone reads it, someone re-types it. Redlines, then Zeplin, then Dev Mode — each one narrowed the gap but never closed it, because a human was still transcribing between two systems that had no shared vocabulary.

MCP closes it by making the design file queryable instead of viewable. The agent doesn't look at a picture of your button and guess. It asks the file what the button is, and the file answers: action.primary, space.stack.md, these variants, these modes.

That is exactly the argument you already make about tokens — decisions should live in one place and be consumed, never re-typed. MCP is that principle extended past the boundary of the design tool. You're not learning a new philosophy here. You're learning the transport layer for one you've been arguing for years.
