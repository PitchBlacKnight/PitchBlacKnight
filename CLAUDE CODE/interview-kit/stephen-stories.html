Design tokens + architecture

His ask: defined, evolved, or operationalized — connected across Figma, libraries, production.

"…including any challenges you helped solve."

"The architecture I run is three tiers with one-way references — primitives private, semantics as the public API and the only layer that themes, component tokens only for real exceptions. I learned that shape the slow way. At Blue Cross we built the first unified system with YOU FILL: what the 'tokens' actually were then — a Sass variables file? a style guide PDF? how many products consumed it? — no pipeline, so keeping design and code aligned was a human job, and it drifted. 02

Web components + DS engineering

His ask: partnering with senior engineers on reuse, scalability, governance, implementation.

"My best partnership story is being overruled. At Avant the engineers rejected my first semantic token set — the names read like design words, not API names. Specifically YOU FILL: one real before/after name pair if you remember one, e.g. what a 'design word' name looked like vs what shipped. They were right: a semantic token is an interface, and interfaces get named by the people who call them. Since then engineers are in the room before the library exists. My current components are custom elements with shadow DOM, themed entirely through custom properties — the one styling channel that inherits through the shadow boundary, so the token layer can theme an encapsulated component without breaking encapsulation. On governance: I audited my own three-year-old system and found three generations of naming all still resolving. I'd built the entrance and never the exit. Deprecation is now part of the initial architecture, not a cleanup."

Demo moment

Open pathfinder/components/pf-button.js — point at the :host custom-property block. Then flip the mode on the docs page: same markup, both themes. If asked for depth: custom properties pierce the boundary; @property registration doesn't work inside shadow DOM in any browser, so definitions live in light DOM — that's a 2026-current detail almost nobody knows.

Don't claimDeep production web-component experience at the old enterprises — that stack is recent for you. The honest line: "the architecture judgment is old, the element syntax is new, and the second one is the easy part."
03

Advanced Figma

His ask: beyond designing components — variables, slots, properties, modes, automation, and what belongs in the system.

"The deeper work is writing against the file instead of in it. I keep variables as multi-collection alias chains mirroring the tiers, modes switch at the semantic collection only, and I wrote a Plugin API exporter because the REST variables endpoint is Enterprise-only — a plugin is the only portable way to get the full alias graph out. On what belongs in the system: the default answer to a new component is no, then the ladder — does it exist, is it an undocumented prop, can two things compose, does one need a variant, and only then is it new. And I keep current: slots went GA in June, so content flexibility finally has a real home — variants for state, properties for configuration, slots for content shape. Teams spent years abusing variants to fake that third thing."

04

Tool-agnostic systems

His ask: Figma not necessarily the source of truth; tooling can evolve without breaking the connection.

"Tokens live in a neutral DTCG file in Git and a build carries them everywhere — CSS, Swift, the docs, the skill file, and eventually the Figma variables themselves, generated back. Figma becomes a consumer instead of the origin. The migration order is the part people get wrong: you take nothing away. Extract first, generate second — a designer's day doesn't change, the origin does, and drift stops being possible instead of being policed. I hold this opinion partly because I've watched tools die under systems: YOU FILL: one real tool your old teams depended on that's gone or irrelevant now — Zeplin? InVision? Abstract? Sketch libraries? what did losing it cost?. The honest edge: the spec answered modes last October — resolvers in DTCG 2025.10 — but Style Dictionary hasn't implemented them yet. Authoring is settled; the pipeline isn't."

Demo moment

The build fan-out IS this answer: one source directory on screen, four outputs in dist/. Open pathfinder.tokens.json and pathfinder.css side by side — same truth, two consumers. InVision's death is the era-spanning proof: every team that treated a tool as the system lost the system.

Don't claim"W3C standard." It's DTCG 2025.10, a stable Community Group spec — deliberately not a W3C Standard. Precision here reads as expertise.
05

Documentation as truth

His ask: docs aligned with the actual architecture, not drifting from production.

"I answer this one with a confession. My own guide said 43 tokens; the collection had 62. Nobody noticed — including me, and I owned it. And I'd seen the same rot at scale before: YOU FILL: one real memory of documentation drift at BCBS/GE/TransUnion — a wiki nobody trusted? a PDF style guide two versions behind? what did people use instead?. The fix isn't discipline, it's removing the possibility: docs generate from the same source as the code, every artifact carries a hash of what built it, and a staleness check fails CI when they diverge. Docs stopped being a description of the system and became an output of it. Descriptions drift; outputs can't."

Demo moment

The two-state gate, live: node build/metadata.mjs --check passes → hand-edit one line of dist/pathfinder.css → check fails with exit 1 → rebuild → passes. "The doc can't be wrong, because a wrong doc fails the build." (Fix the ks-→pf paths first — drill-day blocker 1.)

Design-to-code

His ask: token pipelines, reusable components, automation, closing the design/shipped gap.

"Design-to-code has two halves and people only do the fun one. Generating code from a design is the fun half. The unglamorous half is mapping components to the real ones in the repo — that's what makes anyone trust the output, and it's the half that gets skipped. At Verizon I worked with Code Connect so Dev Mode showed our actual code instead of generated guesses — YOU FILL: your real scope at Verizon — which components, roughly when, who owned the repo side?. I evaluated the export plugins — Anima, Locofy, Builder — and they're the wrong shape for systems work: they export a finished frame, so you get a one-off. 07

AI + design systems

His ask: hands-on only — implemented, not opinions about AI.

"Claude Code is my daily environment, and the design system work runs through three pieces. Skill files as an output contract — tokens, required states, the accessibility floor travel with every generation, plus a rule that every generated value is annotated with the token it came from, so output is auditable instead of trusted. Generated docs behind a staleness gate. And audit scripts — drift, variant coverage, contrast as token-pair ratios. I ran my own audit against my own production file and it found 47 things, including real contrast failures. I didn't clean it up first — a build that reports its own failures is worth more than a green checkmark. The honest numbers: 10x on mechanical work, zero on decisions, and I wouldn't want it otherwise. Generated code is a draft PR — the risk isn't bad output, it's plausible output nobody checked."

Demo moment — the centerpiece

The governed-generation loop from drill 3.2: fresh session, skill file + tokens only, "build a landing concept — every value annotated with its token." Then audit one value live back to the token file. For a visual finale, the pathfinder-2.0/stage rig assembles token-pure components on screen in about a second per request.

08

Where this is going

His ask: your point of view, and what you'd prioritize modernizing a large system today.

"The system becomes a machine-readable contract. Fifteen years of design systems were documentation for humans; now every artifact has a second consumer that does exactly what the system says. Prose rules can't be followed by a machine; structured rules can't be ignored by one. That moves judgment upstream — decisions happen once, in the system, instead of once per component. Modernizing a large system today, in order: audit so drift is a number; neutral token source generating every platform including Figma; map components to the repo before generating anything; encode rules and inventory as machine-readable files — the inventory is what stops a model generating a fourth button next to your three; and govern the exits. The industry number that frames all of it: only 40% of teams have automated token pipelines. The format war is over. The automation isn't. At enterprise scale AI's failure mode isn't malformed output — it's duplication. The system's job is to make generating a duplicate harder than finding the original."
