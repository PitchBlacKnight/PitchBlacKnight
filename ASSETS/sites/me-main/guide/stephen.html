01

Design tokens + architecture

His words: "Where you've helped define, evolve, or operationalize design token architecture… how you've connected tokens across Figma, component libraries, and production code, including any challenges you helped solve."

The three verbs matter: define (Pathfinder), evolve (2.0 → 3.0), operationalize (the exporter + pipeline). Hit all three.

Three tiers, and they only reference one direction. Primitives are the raw scale and nothing touches them directly. Semantics carry the meaning — that's the public API, and the only layer that themes. Component tokens exist only where one component genuinely breaks from the rest.

Pathfinder — Avant

define + evolve
Environment

Fintech advisory platform. Three years full-time, system owned end to end. Enterprise deals previously run out of inboxes and spreadsheets.

What I owned

The whole token architecture — tier structure, naming, theming strategy — plus the component library built on it.

Decisions

Semantic layer as the only theming surface. Engineers named the semantic tokens with me — they pushed back on my first set for reading like design words instead of API names, and they were right.

What changed

2.0 → 3.0 with no redesign. A token layer that survives a major version has the architecture right. One that gets replaced didn't.

Edison — GE Healthcare

evolve at scale
Environment

Forty-plus regulated healthcare products, four theme targets: light and dark, across desktop and touch.

What I owned

The theming model — how one semantic layer resolves to four targets without components forking.

Decisions

Components never fork per theme. Same component; the layer underneath resolves differently.

What changed

Four targets, one component set. The moment you have a "dark version" of a component as a separate component, you've doubled maintenance forever.

DTCG exporter — the operationalize story

the challenge he asked for
Environment

Tokens living as Figma variable collections — architecture invisible to the build.

What I owned

Wrote the plugin: pulls variable collections out as W3C DTCG token JSON so tokens can leave Figma and feed a pipeline.

The challenge

Keeping the aliases. Flatten the semantic layer into resolved values and you get a file that's technically valid and architecturally dead. Also: Figma has one FLOAT type where the spec distinguishes dimension from number — fixed upstream, in the naming convention.

What changed

Tokens became buildable. One source now emits CSS, iOS, and docs — Figma stopped being the only place the architecture existed.

Web components + design system engineering

His words: "How you've partnered with senior engineers to make decisions around reusable components, scalability, governance, and implementation."

Note the framing: he's asking about the partnership, not the components. Lead with a decision engineers changed.

The naming story is the partnership story: a semantic token is an interface, and interfaces get named by the people who call them. At Avant the engineers rejected my first token set for reading like design words. That review — before anything was built — is the collaboration model.

Keystone — the unbranded reference system

web component architecture
Environment

Built as a working demonstration: 101 tokens × 2 modes, custom elements, one build pipeline.

What I owned

Everything — token source, build, and the components: custom elements with shadow DOM, styled entirely by CSS custom properties.

Decisions

Custom properties are the API because they inherit through the shadow boundary — the one styling channel that respects encapsulation and still lets the token layer theme everything. Anatomy fixed; variants change appearance, never structure.

What changed

Same tokens drive CSS, iOS, docs, and the components — change a token, every consumer moves. Framework-agnostic by construction, which is the point of web components.

04

Tool-agnostic design systems

His words: "Building a design system where Figma isn't necessarily the source of truth… documentation, tokens, components, and production code stay connected while allowing the tooling itself to evolve."

This is why the role exists. It was in the JD, he asked about it live, and it's back again here. Your longest answer belongs to this section.

Tokens live in a neutral W3C-format file in Git, and a build carries them out to every consumer — CSS, iOS, docs, and the Figma variables themselves. Figma becomes a consumer instead of the origin. Swap any tool and the contract survives, because the contract was never inside a tool.

The migration order — the part people get wrong

operational, not theoretical
Environment

Any org where Figma is currently the de facto source of truth — which is nearly all of them.

The decision

You don't take anything away. First the exporter pulls the existing variables out to neutral JSON. Then the neutral source starts generating the Figma variables back. Designers' day doesn't change; the origin does.

The challenge

Aliases again — the migration only works if the semantic structure survives the round trip. And honestly: the DTCG spec still has no settled answer for modes. I name that as open rather than pretending it's solved.

What changed

Drift stops being possible instead of being policed. Figma could be replaced tomorrow and the system wouldn't notice.

Land on this "The order matters — you make the neutral source generate the Figma variables, so nothing changes for a designer except that drift stops." That sentence is the whole answer.
05

Documentation as a source of truth

His words: "Keeping documentation aligned with the actual component and token architecture rather than maintaining something that becomes disconnected from production."

You have the perfect story here because it's a confession with a fix, not a claim.

You generate documentation from the same source as the code, or it rots. And I know that because mine did — I went back through my own system and the guide said forty-three tokens when the collection had sixty-two. Nobody noticed. Including me. For years.

The fix — docs as a build artifact

Keystone pipeline
Environment

Keystone: token source in Git, docs previously the classic hand-maintained kind.

What I owned

The build now emits the documentation from the same token file that emits the CSS — the 43-vs-62 failure is structurally impossible.

Decisions

Provenance stamped into every generated artifact — a hash of the source it was built from. A check compares hashes and fails CI when docs are stale. Freshness became a build gate, not a virtue.

What changed

Docs stopped being a description of the system and became an output of it. Descriptions drift; outputs can't.

06

Design-to-code

His words: "Token pipelines, reusable components, automated workflows, or reducing the gap between what exists in design and what gets shipped."

Your position: make handoff not be a thing that happens — then show the three mechanisms that get you there.

Design-to-code has two halves, and people only ever do the fun one. The fun half is generating code from a design. The unglamorous half is mapping each component to the real thing in the repo — that's the half that makes anyone trust the output, and it's the half that gets skipped.

Code Connect — Verizon

the unglamorous half, done
Environment

Verizon design system work, parity across iOS, Android, and web.

What I owned

Wired up Code Connect: every mapped component in Dev Mode shows the team's actual production code, not a generated guess at it.

Decisions

Specs ship with states enumerated and theming hooks in place, so implementation isn't a re-draw. The engineer's first look at a component is the real API.

What changed

The design-code gap stopped being negotiated per handoff. Roughly 85–90% of generated-code styling error comes from skipping exactly this mapping.

Why not the export plugins

the evaluated alternative
What I evaluated

The plugin route — Anima, Locofy, Builder — for system work.

The verdict

Wrong shape for a design system: they export a finished frame, so you get a one-off. Fine for a landing page, poison for a system.

What I use instead

The Figma MCP server inside Claude Code — it reads the live file, real variable names and values, not a snapshot or a screenshot to infer hexes from.

The stack

MCP reads the truth, Code Connect maps to the repo, skill files carry the rules. Miss any one and you're back to output that looks right and isn't.

08

Where you see this going

His words: "How do you think enterprise design systems need to evolve as AI becomes more integrated… what would you prioritize if you were helping modernize a large design system today?"

This is the differentiator question. Everyone else will say "AI will help us move faster." Have an actual thesis and a five-step plan.

The system becomes a machine-readable contract. For fifteen years design systems were documentation for humans; now every artifact — tokens, component inventory, accessibility rules — has a second consumer that will do exactly what the system says. If the rules are prose, AI can't follow them. If they're structured, it can't ignore them. AI doesn't remove the judgment — it moves it upstream: the design work happens once, in the system, instead of once per component.

Modernizing a large system today — in order

the priority list
1 · Audit first

Make drift a number instead of a feeling. You can't modernize what you haven't counted.

2 · Neutral token source

DTCG JSON in Git, build fans out to every platform — Figma included. Additive migration; nobody's workflow breaks.

3 · Map, don't generate

Code Connect before any code generation. Trust comes from the mapping, not the model.

4 · Encode the rules

Skill files: tokens, required states, the accessibility floor, provenance annotation. The inventory too — that's what stops a model generating a fourth button alongside your three.

5 · Govern the exits

A deprecation path, and adoption measured by team — a bare percentage is theatre. Eighty percent tells you nothing about which teams the other twenty are, or why.

Close on this "At enterprise scale the failure mode isn't malformed output — it's duplication. The system's job is to be the thing that makes generating a duplicate harder than finding the original."
